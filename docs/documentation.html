    • PropAgent Documentation

    Welcome to the official deployment and operations guide for PropAgent – the AI-powered tenant screening and property management platform. Follow this step-by-step documentation to set up, customize, and maintain your SaaS instance.

    1. Introduction

    PropAgent is a state-of-the-art property management SaaS platform designed to solve the single largest friction point for landlords and property managers: tenant screening. By incorporating conversational Artificial Intelligence, PropAgent moves beyond simple forms to run interactive text-based interviews with rental applicants. The system automatically assesses key details such as employment status, references, income-to-rent ratios, and general fit to generate detailed risk scores and clear warnings.

    Built with Next.js 15, TypeScript, Tailwind CSS, and MongoDB, PropAgent provides a completely secure, rate-limited, self-hosted solution. It is ideal for property owners, independent landlords, real estate syndicates, or developers looking to launch their own SaaS screen-and-rent platform.

    Advisory Screening Disclaimer

    PropAgent's AI scoring engine is designed as an advisory helper. Final decisions regarding lease approvals remain the exclusive responsibility of the landlord or property manager. The system does not conduct background check or credit reporting integrations out of the box due to local regulatory compliance, putting absolute data ownership in your hands.

    2. System Requirements

    Before launching the PropAgent installation, ensure your hosting server or local machine meets the following environment specifications:

    Node.js Environment
    Node.js 20+ (LTS Recommended). Standard packet managers like NPM v9+ are required for installing and maintaining server modules.
    Database
    MongoDB v7.0+. Supports local community server installations or cloud managed instances (e.g. MongoDB Atlas clusters).
    Docker (Optional)
    Supports containerization for local development database instances using Docker Compose. Simple config included.

    To enable the full scope of AI screening capabilities, a billing-active API Key is required from an LLM provider such as OpenAI (recommend GPT-4o-mini), OpenRouter, or Google Gemini. Additionally, a free Stripe account is required for platform-wide subscription billing configuration.

    3. Installation Guide

    Follow these step-by-step terminal commands to set up the project on your development system or production VPS server:

    1. Clone and Install Project Modules

    Extract the purchase files, enter the project root directory, and run the dependency installation command:

    Bash 
    # Install project dependencies
npm install

    2. Prepare Environment File

    Copy the sample configuration file to create your local active environment file:

    Bash 
    # Create local environment config
cp .env.example .env.local

    Open `.env.local` in your editor and configure your database, secret tokens, encryption keys, and fallback settings as detailed in the Environment Setup section.

    3. Deploy MongoDB (Optional via Docker Compose)

    If you do not have MongoDB running locally, copy this simple configuration block into a local `docker-compose.yml` file to spin up a background database container instantly:

    yaml 
    version: '3.8'

services:
  mongodb:
    image: mongo:latest
    container_name: propagent-db
    ports:
      - "27017:27017"
    volumes:
      - mongo-data:/data/db

volumes:
  mongo-data:

    Launch the database container in detached mode:

    bash 
    # Start MongoDB background container
docker-compose up -d

    4. Seed the Database

    Execute the idempotency seeder script to populate your database collections with default system settings, roles, sample properties, applications, leases, and mock AI screenings:

    Bash 
    # Execute seeder script
npm run seed

    5. Launch Development Server

    Start the Next.js local development process:

    Bash 
    # Start development server
npm run dev

    Open http://localhost:3000 in your browser to view the application.

    6. Build & Deploy for Production

    To compile the optimized Next.js static and server assets for public release:

    Bash 
    # Compile static artifacts
npm run build

# Launch production server
npm run start

    4. Environment Setup

    The system requires certain variables to be defined in `.env.local` to start. Below is a breakdown of all parameters, their function, and standard examples:

    Variable Description Example / Default
    NEXT_PUBLIC_APP_URL Base application URL (used to generate screening link invites). http://localhost:3000
    APP_NAME Default name of the application displayed in headers and emails. PropAgent
    MONGODB_URI Connection string for the MongoDB instance. mongodb://localhost:27017/propagent
    JWT_SECRET Secret token key used to sign and sign-verify user sessions. your-random-64-char-session-secret
    JWT_EXPIRES_IN Session duration before token expires (e.g. 7 days). 7d
    ENCRYPTION_KEY A cryptographic 32-character key used to encrypt sensitive DB credentials like SMTP passwords and API keys. your-random-32-char-crypt-key-here
    UPLOAD_DIR Target filesystem path where unit photographs and lease PDFs are saved. public/uploads
    MAX_FILE_SIZE_MB Enforced limit for documents and photo attachments. 5
    AI_PROVIDER Fallback AI provider to connect with (openai, openrouter, custom). openai
    AI_MODEL Fallback model to initiate screening transcripts and scoring. gpt-4o-mini
    SMTP_HOST Hostname of the email SMTP outbound server. smtp.gmail.com
    SMTP_PORT Port to execute outbound SMTP transactions (usually 587 or 465). 587
    SMTP_USER SMTP provider account username. your-smtp-username
    SMTP_PASS SMTP provider account password or app password. your-smtp-password
    SMTP_FROM Sender address displayed on outgoing emails. noreply@yourdomain.com
    CRITICAL ENCRYPTION KEY REQUIREMENT

    You MUST specify a secure 32-character string in ENCRYPTION_KEY before running the seeder or registering any settings. If you change this key later, values stored encrypted in MongoDB (such as SMTP and LLM passwords) will fail decryption, resulting in errors. Refer to the Troubleshooting section for fix details.

    6. AI Provider Config

    PropAgent supports multiple LLM providers. Super Admins can adjust the system-wide AI configuration directly from the Admin Control Panel → Settings → AI Configuration tab. The API key is securely encrypted before being saved in MongoDB.

    Select your provider below to view configuration instructions:

    OpenAI Configuration (Recommended)

    Connect directly to OpenAI's endpoints. This setup offers low latency for tenant screening interviews and structuring JSON analysis.

    • AI Provider: openai
    • AI Base URL: (Leave completely blank)
    • AI API Key: Your OpenAI API key (looks like sk-proj-...)
    • AI Model: gpt-4o-mini (highly cost-effective) or gpt-4o
    Cost Optimization Tip

    We strongly recommend using gpt-4o-mini. It yields high-quality analysis of tenant screening transcripts while keeping token consumption costs extremely low (typically less than $0.005 per interview session).

    OpenRouter Setup

    OpenRouter lets you route requests to hundreds of different open-source and proprietary models (such as Claude, Llama 3, or Mistral).

    • AI Provider: openrouter (or choose custom)
    • AI Base URL: https://openrouter.ai/api/v1
    • AI API Key: Your OpenRouter API key (looks like sk-or-...)
    • AI Model: E.g., meta-llama/llama-3-8b-instruct or google/gemini-flash-1.5

    Google Gemini (via OpenAI Compatibility)

    Access Google's Gemini models directly using Gemini's native OpenAI-compatible interface.

    • AI Provider: Choose custom (or gemini if available)
    • AI Base URL: https://generativelanguage.googleapis.com/openai/v1
    • AI API Key: Your Google Gemini API Key
    • AI Model: gemini-1.5-flash or gemini-1.5-pro

    Custom OpenAI-Compatible Endpoints

    Connect to local LLM frameworks (such as LM Studio or Ollama) or other third-party inference providers (like Together AI or DeepSeek).

    • AI Provider: Select custom
    • AI Base URL: Set to your endpoint (e.g. https://api.deepseek.com/v1 or http://localhost:1234/v1)
    • AI API Key: Required API key or placeholder text
    • AI Model: Model identifier (e.g., deepseek-chat)

    7. Email SMTP Setup

    PropAgent triggers transactional emails when new screening invitations are issued, application statuses change, leases are finalized, or maintenance requests are modified. The outgoing mail is configured under Admin Panel → Settings → SMTP Configuration.

    Select your mail provider to view setup details:

    Gmail SMTP Setup

    Gmail is excellent for small scale transactional testing. For security, you must use an App Password rather than your primary Google Account password.

    • SMTP Host: smtp.gmail.com
    • SMTP Port: 587
    • SMTP User: Your full Gmail Address (e.g. yourcompany@gmail.com)
    • SMTP Pass: Generated 16-character Google App Password
    • SMTP From: yourcompany@gmail.com
    How to generate a Google App Password

    Go to Google Account Settings → Security. Ensure 2-Step Verification is enabled, then search for "App Passwords". Generate a new password, select "Other (Custom Name)", name it "PropAgent", and copy the 16-letter code into your SMTP settings.

    Enterprise SMTP Setup (SendGrid, Mailgun, Amazon SES)

    Recommended for production SaaS deployments. Ensure you use a verified domain inside your email console to prevent outbound messages from landing in spam.

    Example (SendGrid):

    • SMTP Host: smtp.sendgrid.net
    • SMTP Port: 587
    • SMTP User: apikey
    • SMTP Pass: Your SendGrid API Key
    • SMTP From: noreply@yourdomain.com

    Mailtrap Setup (Development)

    Excellent for inspecting email styling locally without triggering actual outbound messages to users.

    • SMTP Host: smtp.mailtrap.io
    • SMTP Port: 2525 (or 587)
    • SMTP User: Mailtrap Inbox Username
    • SMTP Pass: Mailtrap Inbox Password
    • SMTP From: dev@propagent.com

    8. User Roles Explained

    PropAgent implements role-based access control (RBAC). Each role has access to specific dashboards and functions:

    Super Admin
    The platform owner. Super Admins manage the platform settings, configure the system-wide AI and SMTP credentials, manage subscription plans, view revenue analytics, configure Stripe settings, audit registrations, view metrics across all landlords, and activate or deactivate landlord accounts.
    Landlord / Property Manager
    The primary system user. Landlords register their property lists, configure custom units, subscribe to subscription plans, manage their billing and invoices at `/billing`, view dashboards containing active tenant stats, review AI-graded applicant summaries, issue leases, manually log payments, and track maintenance tickets.
    Tenant (and Applicant)
    End users. Applicants fill out rental applications online and complete the interactive AI screening interviews. Approved tenants use their portal to review active lease agreements, check rent status, view payment history, and report maintenance issues (with no billing involvement).

    9. Feature Walkthrough

    Explore the main functional blocks that drive the PropAgent SaaS product:

    🤖 Interactive AI Screening Portal

    Prospective tenants submit details via a public application page. Once submitted, they are routed to an interactive chat portal where the AI interviewer asks follow-up screening questions. The conversation is stored dynamically in MongoDB, allowing landlords to review transcripts at any time.

    📊 Intelligent Risk Assessment & Flags

    The system parses the interview log, compares parameters against landlord rules, and outputs a clean dashboard grading system (0-100 score). The scoring engine displays warnings for income discrepancies, short employment terms, or landord reference flags.

    🏘️ Property & Unit Management Console

    Landlords can easily create properties, manage unit occupancy states, upload unit images, and configure rental terms. Custom filters allow landlords to check occupancy rates and monitor portfolio health at a glance.

    📑 Lease Ledger & Document Repository

    Upon application approval, the system pre-fills details to generate a lease agreement. Landlords can log lease parameters, upload signed lease agreements (PDFs), track expiration timers, and log lease extensions.

    💳 Manual Rent Logging & Receipts

    Landlords can manually log rent payments, record payment methods (online, cash, bank transfer), and add ledger notes. This allows landlords to keep a digital log of tenant histories without third-party payment system overhead.

    🔧 Tenant Maintenance Portal

    Tenants can log maintenance tickets directly from their portal, attach photographs, and specify urgency levels (Low, Medium, Urgent). Landlords can update ticket statuses (Open, In Progress, Resolved) and keep private internal notes on vendor coordinates.

    🔒 Security and Rate Limiting Utilities

    PropAgent includes sliding-window rate limiters to protect authentication routes (max 10 attempts/15 mins) and screening portals (max 3 applications/hour). Recursive input sanitization strips HTML tags to protect the database, and ownership audits prevent unauthorized access to records.

    💳 Subscription & SaaS Billing Module

    PropAgent is fully equipped for SaaS operations. Super admins can create, customize, and feature subscription plans (Free, Pro, Business) directly from the dashboard. The system automatically enforces feature-level limits (such as limits on the number of properties, units, or AI screenings). Landlords can manage their subscriptions self-service using the integrated Stripe Customer Portal, which handles card updates, cancellations, and invoices.

    10. Subscription & Billing

    PropAgent is fully prepared for commercial operations with a built-in Stripe SaaS subscription model. You can charge landlords recurring fees, enforce feature-level limits, and allow self-service subscription management.

    How It Works

    PropAgent is designed to be run as a SaaS business. You (the platform operator) charge landlords a subscription fee. Landlords manage their properties and tenants on your platform. Tenants use the platform for free.

    You (Platform Operator)
    ➔ sells access to ➔
    Landlords
    ➔ manage ➔
    Tenants

    Subscriptions in PropAgent flow through standard lifecycle statuses, mapped directly to their Stripe state:

    Status Description Access Granted
    trialing Landlord is in an active trial period without being billed yet. Full access matching their selected trial plan.
    active The subscription is active, and payments are up to date. Full access matching the active plan limits.
    past_due A payment failed. Stripe is retrying payment collection. Full access, but warning banners prompt the user to update cards.
    cancelled The user has cancelled billing, but the current billing cycle is still active. Access continues until the end of the current billing cycle.
    expired The subscription is fully terminated, or trial expired without payment. No access to premium landlord dashboards/actions. Restricted back to Free limits.
    none No active subscription record exists (e.g. initial registration). Defaults to the base Free plan limits.

    Managing Plans

    Platform operators can view, edit, and create subscription packages directly from the Super Admin dashboard:

    • Access Path: Log in as Super Admin → Navigate to the Plans page.
    • Default Seeding: Seeding details are described in the setup section below, establishing Free, Pro ($29/mo), and Business ($79/mo) plans.
    • Creating Custom Plans: Click Add New Plan, specify details, monthly price, trial days, and feature limits.
    • Feature Plan Toggle: Check the "Featured" option on a plan to render a prominent "Most Popular" highlight on the registration and billing pricing cards.
    • Subscribers Dependency Warning: To protect database integrity and active payment routes, you cannot delete a subscription plan that has active subscribers. Delete options are deactivated for populated plans.

    Each subscription plan enforces limits across key features:

    Limit Type Scope & Description
    Properties Limit The total number of properties a landlord is allowed to add to their portfolio.
    Units Limit The total number of rental units across all property addresses.
    AI Screenings Limit The maximum number of candidate interviews conducted by the AI agent per billing cycle.
    Lease Limit The maximum number of digital leases and payment ledger logs that can be registered.

    Stripe Setup Guide

    Configure Stripe API communication and sync products with your platform setting tabs:

    1. Prerequisites: Create a free developer or merchant account at stripe.com.
    2. Get API keys: Go to Stripe Dashboard → Developers → API Keys. Copy the Publishable Key and Secret Key.
    3. Enter keys: Paste the credentials under Admin Panel → Settings → Stripe Config tab and click Save Config.
    4. Sync Plans: Click "Sync Plans to Stripe". The platform will automatically push your local database plans as Products and Prices in Stripe.
    5. Set up webhook:
      • LOCAL DEV:
        • Install Stripe CLI: brew install stripe/stripe-cli/stripe
        • Log in: stripe login
        • Forward events: stripe listen --forward-to localhost:3000/api/webhooks/stripe
        • Copy the displayed signing secret (whsec_...) and place it under STRIPE_WEBHOOK_SECRET in .env.local.
      • PRODUCTION:
        • Go to Stripe Dashboard → Developers → Webhooks → Add Endpoint.
        • Set URL to: https://yourdomain.com/api/webhooks/stripe
        • Select the events: checkout.session.completed, customer.subscription.updated, customer.subscription.deleted, customer.subscription.trial_will_end, invoice.payment_failed, invoice.payment_succeeded
        • Copy the production signing secret to STRIPE_WEBHOOK_SECRET in your production environment variables.
    6. Test: Complete trial payments and checkout testing using test card number 4242 4242 4242 4242 (enter any future date and 3-digit CVC).
    7. Go Live: Swap test API keys for live keys in your Admin Panel settings when ready to accept real payments.

    Landlord Billing Experience

    The billing flow is built to be self-service and low-friction for landlords:

    1. Registration: Upon creating a landlord account, the system automatically assigns them to the default **Free** plan.
    2. Encountering Limits: If a landlord attempts to add more properties or units than allowed, a warning alert triggers redirecting them to the Billing section.
    3. Plan Upgrade Selection: Landlords navigate to /billing to compare the features of the Free, Pro, and Business plans.
    4. Stripe Checkout Session: Clicking Upgrade securely redirects the landlord to Stripe Checkout with your pre-synced prices.
    5. Dashboard Return: Once payment succeeds, the landlord returns to your app, and webhooks instantaneously upgrade their plan in your database.
    6. Self-Service Billing Portal: At any time, landlords can click Manage Billing on /billing to access the Stripe Customer Portal, allowing them to download payment invoices, update card credentials, or switch/cancel plans.

    Revenue Dashboard (Super Admin)

    The Super Admin panel includes key SaaS analytics to monitor product metrics:

    • Dashboard Access: Log in as Super Admin → Navigate to the Subscriptions page.
    • Metrics Explained:
      • MRR (Monthly Recurring Revenue): The sum of predictable monthly subscription fees generated by active landlords.
      • ARR (Annual Recurring Revenue): The annual forecast of recurring subscription fees, calculated as MRR × 12.
      • Active Subscribers: Total count of landlords currently on paid tiers.
    • Manual Plan Override: Admins can manually override a landlord's active plan directly from the Landlords list, bypassing Stripe checks to offer customized access level changes.
    • Force Cancellation: Click Cancel Subscription next to a landlord's record to cancel active Stripe billing records instantly.
    • Landlord Usage Auditing: Inspect landlord records to audit current usage statistics against their plan limit counts (e.g. viewing how many AI screenings a landlord has left).

    11. Customization Guide

    Deployers can easily customize PropAgent's look and feel, brand name, and AI prompts to suit their needs:

    Changing Brand Name & Logo

    Change your application's public identity globally by editing the APP_NAME variable inside your `.env` file, or by logging into the Super Admin panel settings. You can upload custom corporate logo graphics from the dashboard.

    Modifying Theme Palette (Tailwind CSS)

    To change the color scheme, edit the color variables inside `tailwind.config.ts`. For example, you can adjust the primary indigo color theme:

    TypeScript 
    // tailwind.config.ts
theme: {
  extend: {
    colors: {
      primary: {
        50: '#f5f3ff',
        500: '#8b5cf6', // Modify to set your new primary color
        600: '#7c3aed',
      }
    }
  }
}

    Adjusting the AI Screening and Scoring System Prompts

    The AI interviewer's persona, interview focus, and scoring criteria can be customized by editing the variables in lib/prompts.ts:

    • SYSTEM_PROMPT_TEMPLATE: Configures the conversational persona, structure, and tone of the AI interviewer.
    • SCORING_SYSTEM_PROMPT: Configures the assessment parameters and rules used to generate risk reports.

    12. Troubleshooting FAQs

    Resolve the most common configuration issues using these solutions:

    1. Database Connection Failures (MongoNetworkError)

    Cause: MongoDB service is not running or the URI is incorrect.
    Solution: Verify that MongoDB is active (`brew services list` or run `docker ps` if containerized). Ensure your password in `.env.local` is URL-encoded if it contains special characters.

    2. OpenAI API Errors or Zero Quota Responses

    Cause: Missing API credit, wrong credentials, or rate limits.
    Solution: Verify credit status in your OpenAI portal. Go to Admin → Settings → AI Config and ensure the model matches your API key access level (e.g., use gpt-4o-mini).

    3. Transactional Emails Not Delivering

    Cause: Incorrect SMTP configurations or blocked accounts.
    Solution: Verify host details and use port 587 with TLS. If using Gmail, you must use an App Password. Ensure the SMTP_FROM address is a verified domain with your email provider.

    4. Upload Failures or Permission Denied (EACCES)

    Cause: Missing directories or restricted folder permissions.
    Solution: Ensure your Node process has write access to the uploads directory. Run chmod -R 775 public/uploads to verify permissions.

    5. Users Logout Immediately / JWT Expiration

    Cause: JWT_SECRET changes on restart or session timers are too short.
    Solution: Set a static string for JWT_SECRET in `.env.local` to prevent session invalidations during server restarts, and set JWT_EXPIRES_IN=7d.

    6. Next.js Static Build Hydration/Compiling Errors

    Cause: Server-side files are evaluated statically during build phases without DB access.
    Solution: Ensure MongoDB is accessible during builds, or add export const dynamic = 'force-dynamic' to routes that pull data dynamically.

    7. User blocked with 429 Status code

    Cause: Custom rate limiters blocking repetitive requests.
    Solution: This is expected during automated security tests. Restart the Next.js process to clear the in-memory cache and reset rate-limiting history.

    8. Setting decryption errors after changing ENCRYPTION_KEY

    Cause: Stored settings cannot be decrypted because the encryption key changed.
    Solution: If you update your ENCRYPTION_KEY, old credentials stored in MongoDB will fail to decrypt. Run a database command to delete the document in the systemsettings collection and re-run npm run seed to generate clean settings with your new key.

    9. Webhook events not received locally

    Cause: Stripe CLI listener is not running or the webhook secret is out of date.
    Solution: Ensure stripe listen is running in a separate terminal. The signing secret changes each time you launch the CLI, so verify that the STRIPE_WEBHOOK_SECRET in .env.local matches the terminal output.

    10. Stripe sync fails with "No secret key configured"

    Cause: You clicked "Sync Plans to Stripe" before saving your secret key.
    Solution: Navigate to **Admin → Settings → Stripe Config**, enter your Stripe Secret Key, click **Save Config**, and then click **Sync Plans to Stripe**.

    11. Landlord upgraded but plan didn't change

    Cause: Webhook events are not being received by the application server.
    Solution: Check if your webhook listener (like stripe listen) is running. You can trigger a mock checkout webhook event to test integration with: stripe trigger checkout.session.completed.

    12. Plans page shows no plans

    Cause: Default plan seeding was not performed.
    Solution: Send a POST request to /api/admin/plans/seed-defaults, or visit /api/admin/plans/seed-defaults in your browser while authenticated as a super_admin.
